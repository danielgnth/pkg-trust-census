### Sigstore across registries (verified 2026-10-14)

4 of 7 registries accept Sigstore bundles (npm, PyPI, RubyGems, Maven Central), all logged in the
public Rekor instance. In the trust matrix each bundle counts as a publisher signature and a transparency-log entry.

| | Sigstore | Since | Latest releases with a bundle | Registry verifies on upload | Best install client | Nearest equivalent |
|---|---|---|---:|---|---|---|
| **PyPI** | ✓ yes | 2024-11 | 64% (32/50) | yes | no (pip 26) | None left: PGP signature uploads were removed in 2023. |
| **npm** | ✓ yes | 2023-04 | 20% (10/50) | yes | opt-in (npm 12) | Registry-applied ECDSA signatures on every tarball (dist.signatures), also checked only by `npm audit signatures`. |
| **crates.io** | ✗ no | – | – | n/a | n/a | None deployed. A TUF signing experiment exists; trusted publishing records the commit from the CI's OIDC token, but nothing is signed for consumers. |
| **RubyGems** | ✓ yes | 2024-12 | 26% (13/50) | yes | no (gem / Bundler 4) | Legacy X.509 `gem cert` signatures: opt-in to verify, rarely used, not exposed by the API. |
| **Go** | ✗ no | – | – | n/a | n/a | sum.golang.org, Google's own append-only Merkle log of module hashes with signed tree heads, checked by the go command by default. A transparency log like Rekor, but of hashes, not publisher identities. |
| **Maven Central** | ✓ yes | 2025-01 | 0% (0/50) | yes | no (Maven 3/4) | Mandatory PGP signatures on every file: long-lived publisher keys, not logged, not checked by Maven by default. |
| **Packagist** | ◐ planned | – | – | n/a | n/a | A login-gated log of security events (ownership, maintainers, version references); not a log of artifacts. |

No install client checks Sigstore bundles by default, including newer ones (uv, pnpm, Yarn, Bun, Gradle).
The only check is npm's opt-in `npm audit signatures`, run after install.

#### What is signed, and sources

- **PyPI**: Each distribution file, by the Trusted Publisher's CI identity (PEP 740), served through the Integrity API. Most bundles carry the publish predicate, not SLSA provenance. [1](https://blog.pypi.org/posts/2024-11-14-pypi-now-supports-digital-attestations/ "“PyPI package maintainers can now publish signed digital attestations when publishing” … “The Integrity API provides programmatic access to PyPI's implementation of PEP 740.” (accessed 2026-10-14)") [2](https://peps.python.org/pep-0740/ "“Each bundle corresponds to a signing identity (such as a Trusted Publishing identity), and contains one or more attestation objects.” (accessed 2026-10-14)") [3](https://pip.pypa.io/en/stable/topics/secure-installs/ "“By default, pip does not perform any checks to protect against remote tampering” (accessed 2026-10-14)") [4](https://blog.pypi.org/posts/2023-05-23-removing-pgp/ "“any PGP signatures will be silently ignored” (accessed 2026-10-14)")
- **npm**: The tarball, by the publisher's CI identity (Fulcio), as SLSA provenance in dist.attestations; npm adds a publish attestation signed with its own registry key. Both are logged in the public Rekor. [1](https://github.blog/changelog/2023-09-26-npm-provenance-general-availability/ "“npm provenance is now generally available.” (accessed 2026-10-14)") [2](https://docs.npmjs.com/generating-provenance-statements "“When an npm package is published with provenance, it is signed by Sigstore public good servers and logged in a public transparency ledger” (accessed 2026-10-14)") [3](https://github.com/npm/provenance "“When verification is succesful npm attests the publish with by signing a publish attestation.” (accessed 2026-10-14)") [4](https://docs.npmjs.com/verifying-registry-signatures "“Registry signatures can be verified using the following `audit` command:” (accessed 2026-10-14)")
- **crates.io**: Nothing: the Sigstore RFC for Cargo (#3403) was closed unmerged in 2023. [1](https://github.com/rust-lang/rfcs/pull/3403 "“This proposal will enhance cargo and crates.io through adoption of the Sigstore capabilities and workflows as described in the document.” … “closed this Aug 14, 2023” (accessed 2026-10-14)") [2](https://rust-lang.github.io/goals/2025h1/verification-and-mirroring.html "“We would like to have a experimental out-of-band version of a signing pipeline for the project for releases and crates.io.” (accessed 2026-10-14)")
- **RubyGems**: The .gem, by the CI identity, via `gem push --attestation` (RubyGems 3.6, used by rubygems/release-gem); served at /api/v1/attestations. Accepted only from a trusted-publishing push. [1](https://blog.rubygems.org/2025/01/24/december-rubygems-updates.html "“adding a `--attestation` option to `gem push` for improved security” (accessed 2026-10-14)") [2](https://github.com/rubygems/rubygems.org/blob/master/app/models/pusher.rb "“def initialize(api_key, body, request: nil, attestations: nil)” (accessed 2026-10-14)") [3](https://guides.rubygems.org/security/ "“In practice signing is rarely used” (accessed 2026-10-14)")
- **Go**: Nothing: modules are fetched from VCS and authors cannot sign them. [1](https://go.dev/ref/mod#checksum-database "“It is a Transparent Log (or 'Merkle Tree') of `go.sum` line hashes” (accessed 2026-10-14)") [2](https://go.dev/blog/module-mirror-launch "“The `go` command will use the module mirror and checksum database by default for Go 1.13 module users.” (accessed 2026-10-14)")
- **Maven Central**: Any deployed file, as an optional .sigstore.json next to the mandatory PGP .asc. [1](https://central.sonatype.org/news/20250128_sigstore_signature_validation_via_portal/ "“we have rolled out an update to the Central Publisher Portal that validates Sigstore signature files.” … “Sigstore signature files are not required to publish at this time.” (accessed 2026-10-14)") [2](https://central.sonatype.org/publish/requirements/gpg/ "“One of the requirements for publishing your artifacts to the Central Repository, is that they have been signed with PGP.” (accessed 2026-10-14)")
- **Packagist**: Nothing yet: hosted artifacts with SLSA provenance and Sigstore attestations verified by Composer are a stated direction (2026-05), with news promised 2026-09-29. [1](https://blog.packagist.com/an-update-on-composer-packagist-supply-chain-security/ "“Further out, we want Packagist.org to begin hosting immutable build artifacts directly, alongside SLSA build provenance and Sigstore attestations” … “Packagist.org has a public transparency log (login required) that records security-relevant events across the repository.” (accessed 2026-10-14)") [2](https://blog.packagist.com/15-years-of-packagist-over-200-billion-package-installs/ "“We have some good news to share on that last point in a separate blog post in the next few days.” (accessed 2026-10-14)")

#### Install clients

| Ecosystem | Client | Checks bundles | Note |
|---|---|---|---|
| PyPI | pip 26 | no | Checks file hashes only; no attestation verification. [1](https://pip.pypa.io/en/stable/topics/secure-installs/ "“By default, pip does not perform any checks to protect against remote tampering” (accessed 2026-10-14)") |
| PyPI | uv 0.12 | no | Uploads attestations by default when publishing (since 0.9.12); does not verify them on install. [1](https://docs.astral.sh/uv/reference/cli/#uv-publish "“By default, uv attempts to upload matching PEP 740 attestations with each distribution that is published.” (accessed 2026-10-14)") |
| npm | npm 12 | opt-in | `npm audit signatures` checks attestations and registry signatures of an installed tree; `npm install` itself does not. [1](https://docs.npmjs.com/generating-provenance-statements "“You can verify the provenance attestations of downloaded packages with the following `audit` command: `npm audit signatures`” (accessed 2026-10-14)") |
| npm | pnpm 12 | no | `trustPolicy: no-downgrade` (opt-in, since 10.21) refuses a version whose trusted-publisher/provenance metadata is weaker than an earlier one's, but reads the packument fields without verifying the bundle. `pnpm audit signatures` checks registry ECDSA signatures only. [1](https://pnpm.io/settings/dependency-resolution#trustpolicy "“When set to `no-downgrade`, pnpm will fail if a package's trust level has decreased compared to previous releases.” (accessed 2026-10-14)") [2](https://github.com/pnpm/pnpm/blob/main/pnpm11/resolving/npm-resolver/src/trustChecks.ts "“if (manifest._npmUser?.trustedPublisher && manifest.dist?.attestations?.provenance) { return 'trustedPublisher' }” (accessed 2026-10-14)") [3](https://github.com/pnpm/pnpm/blob/main/pnpm11/deps/security/signatures/README.md "“`verifySignatures()` verifies ECDSA registry signatures for installed package versions.” (accessed 2026-10-14)") |
| npm | Yarn 4 | no | Generates provenance on publish; does not verify on install. [1](https://github.com/yarnpkg/berry/blob/master/packages/plugin-npm/sources/npmProvenance.ts "“export const generateProvenance = async (subject: any, opts?: sigstore.SignOptions) => {” (accessed 2026-10-14)") |
| npm | Bun | no | No attestation handling. [1](https://bun.sh/docs/cli/install "“Skip verifying integrity of newly downloaded packages” (accessed 2026-10-14)") |
| crates.io | cargo | n/a | No bundles to check; checks the index's sha256. [1](https://github.com/rust-lang/cargo/blob/master/src/sources/registry/download.rs "“anyhow::bail!('failed to verify the checksum of `{}`', pkg)” (accessed 2026-10-14)") |
| RubyGems | gem / Bundler 4 | no | Attestations are only sent (`gem push --attestation`); legacy X.509 signatures are checked only with `-P MediumSecurity`. [1](https://github.com/ruby/rubygems/blob/master/lib/rubygems/commands/push_command.rb "“add_option('--attestation FILE', 'Push with sigstore attestations'” (accessed 2026-10-14)") [2](https://guides.rubygems.org/security/ "“users opt into verification with a trust policy, using `gem install -P MediumSecurity`” (accessed 2026-10-14)") |
| Go | go | n/a | No bundles to check; every download is checked against sum.golang.org by default. [1](https://go.dev/blog/module-mirror-launch "“The `go` command will use the module mirror and checksum database by default for Go 1.13 module users.” (accessed 2026-10-14)") |
| Maven Central | Maven 3/4 | no | Checks checksums only; signatures need a plugin. [1](https://www.simplify4u.org/pgpverify-maven-plugin/ "“This plugin allows you to automatically verify PGP signature of all project dependencies.” (accessed 2026-10-14)") |
| Maven Central | Gradle 9 | no | Dependency verification (opt-in, via verification-metadata.xml) checks checksums and PGP .asc signatures, not Sigstore bundles. [1](https://docs.gradle.org/current/userguide/dependency_verification.html "“Checksums alone verify integrity but not authenticity. Signatures alone verify authenticity but may use weak hashes.” (accessed 2026-10-14)") |
| Packagist | Composer 2.10 | n/a | No bundles to check; client-side verification is planned with hosted artifacts. [1](https://getcomposer.org/doc/03-cli.md#install-i "“The `install` command reads the `composer.json` file from the current directory, resolves the dependencies, and installs them into `vendor`.” (accessed 2026-10-14)") |
