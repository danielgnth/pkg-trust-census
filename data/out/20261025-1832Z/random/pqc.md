✓ post-quantum safe (hash ≥ 256 bits or symmetric secret) · ◐ partly (hash-chained log with classical
checkpoint signatures, hybrid TLS with classical certificates, TOTP beside WebAuthn) · ✗ broken by a quantum
computer (RSA, ECDSA, EdDSA) · ⚠ weak already (SHA-1, MD5) · – not used.

Every signature in every ecosystem is classical, Sigstore included (its ML-DSA instance is targeted for
mid-2027). What is already post-quantum safe is the hashing: lockfile and index hashes everywhere except
Maven (SHA-1) and Packagist (git SHA-1), and the Merkle trees under Rekor and sum.golang.org.

#### Notes and sources

**Install hash**: What hash does the default client check or pin a download against?

- PyPI: SHA-256 (safe). pip checks each file against the index's sha256. [1](https://github.com/pypa/pip/blob/main/src/pip/_internal/operations/prepare.py "“if not self.require_hashes: return req.hashes(trust_internet=True)” (accessed 2026-10-14)")
- npm: SHA-512 (safe). dist.integrity (SRI sha512), recorded in package-lock.json. [1](https://docs.npmjs.com/cli/configuring-npm/package-lock-json "“integrity: A `sha512` or `sha1` Standard Subresource Integrity string” (accessed 2026-10-14)")
- crates.io: SHA-256 (safe). Cargo checks the index's cksum and records it in Cargo.lock. [1](https://doc.rust-lang.org/cargo/reference/registry-index.html "“A SHA256 checksum of the `.crate` file.” (accessed 2026-10-14)")
- RubyGems: SHA-256 (safe). Compact-index checksums; Gemfile.lock CHECKSUMS since Bundler 2.6 (opt-in). [1](https://github.com/ruby/rubygems/blob/master/lib/bundler/checksum.rb "“raise(ChecksumMismatchError.new(display_name, existing, checksum))” (accessed 2026-10-14)") [2](https://blog.rubygems.org/2024/12/19/bundler-v2-6 "“For a single lockfile, you can run `bundle lock --add-checksums`.” (accessed 2026-10-14)")
- Go: SHA-256 (safe). go.sum h1: hashes (SHA-256 over a file-hash list), checked against the checksum database. [1](https://go.dev/ref/mod#checksum-database "“the go command may connect to the checksum database to verify cryptographic hashes of modules not listed in go.sum” (accessed 2026-10-14)")
- Maven Central: SHA-1 / MD5 (weak). Central serves .sha1 and .md5 for every file (.sha256/.sha512 optional); Maven 3 checks SHA-1 and only warns on mismatch. SHA-1 collisions are practical today. [1](https://maven.apache.org/resolver/about-checksums.html "“Most Maven repositories contain SHA-1 and MD5 checksums by default.” (accessed 2026-10-14)") [2](https://issues.apache.org/jira/browse/MNG-5728 "“The default checksum policy when obtaining artifacts during a build is currently, by default, 'warn'.” (accessed 2026-10-14)")
- Packagist: git SHA-1 (weak). dist.shasum is empty for forge archives; the only pin is the commit id, a SHA-1 (GitHub detects known collision attacks, but the hash is SHA-1). [1](https://repo.packagist.org/p2/monolog/monolog.json "“'shasum': ''” (accessed 2026-10-14)")

**MFA**: Which second factors does the registry offer?

- PyPI: TOTP · WebAuthn (partial). Mandatory. TOTP is symmetric; WebAuthn signatures are classical, with public keys known only to PyPI. [1](https://pypi.org/help/#twofa "“'something you own' can be an application to generate a temporary code, or a security device (most commonly a USB key).” (accessed 2026-10-14)") [2](https://blog.pypi.org/posts/2024-01-01-2fa-enforced/ "“PyPI now requires Two-factor authentication (2FA) for all users.” (accessed 2026-10-14)")
- npm: TOTP · WebAuthn (partial). Security keys (WebAuthn) are the documented method and TOTP is being deprecated. TOTP is HMAC-SHA1 over a shared secret (post-quantum safe). Security keys sign with ECDSA/EdDSA, but their public keys are known only to the registry. [1](https://docs.npmjs.com/configuring-two-factor-authentication "“You can enable two-factor authentication (2FA) on your npm user account to protect against unauthorized access to your account and packages using a security-key.” (accessed 2026-10-14)") [2](https://github.blog/security/supply-chain-security/our-plan-for-a-more-secure-npm-supply-chain/ "“Deprecate time-based one-time password (TOTP) 2FA, migrating users to FIDO-based 2FA.” (accessed 2026-10-14)")
- crates.io: via GitHub (partial). Whatever the GitHub account uses: TOTP, WebAuthn/passkeys, GitHub Mobile or SMS. [1](https://docs.github.com/en/authentication/securing-your-account-with-two-factor-authentication-2fa/about-two-factor-authentication "“After you configure 2FA, using a time-based one-time password (TOTP) mobile app, or via text message, you can add a security key” … “You can also use GitHub Mobile for 2FA after configuring a TOTP mobile app or text messages.” (accessed 2026-10-14)")
- RubyGems: TOTP · WebAuthn (partial). TOTP is symmetric; WebAuthn signatures are classical, with public keys known only to rubygems.org. [1](https://guides.rubygems.org/setting-up-multifactor-authentication/ "“You may enable MFA using WebAuthn or by using one-time passwords (OTP).” (accessed 2026-10-14)")
